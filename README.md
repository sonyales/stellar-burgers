# Stellar Burgers

**Stellar Burgers** — frontend-приложение для космической бургерной: пользователь может собрать бургер из ингредиентов, оформить заказ, отслеживать ленту заказов и управлять личным профилем.

Проект реализован как production-like SPA с авторизацией, защищёнными маршрутами, глобальным состоянием, асинхронной работой с REST API, модальными окнами на базе роутинга и тестированием ключевой логики.

## Цель проекта

Цель проекта — разработать полноценное клиентское приложение на React и TypeScript с архитектурой, близкой к реальным коммерческим SPA: разделением бизнес-логики по feature-слайсам, централизованным состоянием, защищённым роутингом, обработкой API-состояний и покрытием основных пользовательских сценариев тестами.

## Основной функционал

### Сборка и оформление заказа

Пользователь может собрать бургер из доступных ингредиентов, посмотреть итоговую стоимость и оформить заказ после авторизации.

Реализовано:

* загрузка ингредиентов с сервера;
* отображение ингредиентов по категориям;
* просмотр детальной информации об ингредиенте;
* сборка бургера в конструкторе;
* расчёт итоговой стоимости заказа;
* оформление заказа только для авторизованных пользователей;
* отображение номера созданного заказа после успешного запроса.

### Авторизация и личный кабинет

В приложении реализован полный пользовательский flow: регистрация, вход, восстановление пароля, выход из аккаунта и редактирование профиля.

Реализовано:

* регистрация пользователя;
* авторизация;
* восстановление и сброс пароля;
* получение и обновление данных пользователя;
* редактирование имени, email и пароля;
* отмена изменений в форме профиля;
* защита приватных маршрутов;
* перенаправление неавторизованных пользователей на страницу входа.

### Лента и история заказов

Приложение содержит публичную ленту заказов и персональную историю заказов пользователя.

Реализовано:

* публичная лента заказов по маршруту `/feed`;
* история заказов пользователя по маршруту `/profile/orders`;
* отображение деталей заказа;
* расчёт стоимости каждого заказа на основе ингредиентов;
* отображение статусов заказов;
* защита персональной истории заказов авторизацией.

## Ключевые инженерные решения

### Архитектура состояния

Глобальное состояние приложения вынесено в Redux store и разделено по функциональным зонам. Для работы с серверными данными и UI-состояниями используются slices, selectors и async thunks.

В store обрабатываются:

* данные пользователя и состояние авторизации;
* список ингредиентов;
* состояние конструктора бургера;
* данные заказов;
* loading- и error-состояния API-запросов.

Такой подход позволяет отделить бизнес-логику от UI-компонентов и централизованно управлять состоянием приложения.

### Работа с API

Взаимодействие с сервером реализовано через REST API. Асинхронные операции вынесены в thunk-функции, которые отвечают за получение данных, создание заказов, авторизацию и обновление профиля.

Для пользовательского опыта предусмотрена обработка состояний загрузки и ошибок: интерфейс корректно реагирует на ожидание ответа сервера и неуспешные сценарии.

### Защищённый роутинг

Приватные маршруты доступны только авторизованным пользователям. При попытке открыть личный кабинет, историю заказов или оформить заказ без авторизации пользователь перенаправляется на страницу входа.

Также реализованы маршруты, доступные только неавторизованным пользователям: вход, регистрация и восстановление пароля.

### Модальные окна через роутинг

Модальные окна ингредиентов и заказов синхронизированы с URL. Благодаря этому пользователь может открыть карточку ингредиента или заказа из интерфейса, перейти по прямой ссылке на отдельную страницу и вернуться назад через историю браузера без потери контекста.

Это поведение реализовано для маршрутов:

* `/ingredients/:id`;
* `/feed/:number`;
* `/profile/orders/:number`.

### Формы и профиль пользователя

Форма профиля работает с контролируемыми полями. При изменении данных появляются кнопки сохранения и отмены. Сохранение отправляет обновлённые данные на сервер, а отмена возвращает форму к исходному состоянию.

Отправка форм обрабатывается через `onSubmit`, что обеспечивает корректное поведение формы и доступность стандартных браузерных сценариев.

## Маршрутизация

| Маршрут                   | Доступ                               | Описание                                 |
| ------------------------- | ------------------------------------ | ---------------------------------------- |
| `/`                       | Все пользователи                     | Конструктор бургеров                     |
| `/feed`                   | Все пользователи                     | Общая лента заказов                      |
| `/feed/:number`           | Все пользователи                     | Детальная страница заказа из общей ленты |
| `/ingredients/:id`        | Все пользователи                     | Детальная страница ингредиента           |
| `/login`                  | Только неавторизованные пользователи | Вход в аккаунт                           |
| `/register`               | Только неавторизованные пользователи | Регистрация                              |
| `/forgot-password`        | Только неавторизованные пользователи | Запрос восстановления пароля             |
| `/reset-password`         | Только неавторизованные пользователи | Сброс пароля                             |
| `/profile`                | Авторизованные пользователи          | Профиль пользователя                     |
| `/profile/orders`         | Авторизованные пользователи          | История заказов пользователя             |
| `/profile/orders/:number` | Авторизованные пользователи          | Детальная страница заказа пользователя   |

## Переменные окружения

Для работы приложения необходимо создать файл `.env` в корне проекта и указать адрес API:

```env
BURGER_API_URL=https://norma.education-services.ru/api
```

Пример переменных окружения находится в файле `.env.example`.

## Запуск проекта

### Клонировать репозиторий

```bash
git clone https://github.com/sonyales/stellar-burgers.git
cd stellar-burgers
```

### Установить зависимости

```bash
npm install
```

### Создать файл окружения

```bash
cp .env.example .env
```

### Запустить приложение

```bash
npm start
```

## Тестирование

В проекте используется несколько уровней тестирования:

* **Jest** — тестирование редьюсеров, селекторов и бизнес-логики;
* **React Testing Library** — проверка компонентов и пользовательских сценариев;
* **Cypress** — e2e-тестирование основных сценариев: сборка бургера, открытие модальных окон, авторизация, оформление заказа и переходы по маршрутам;
* **Storybook** — изолированная разработка и визуальная проверка UI-компонентов.
